# Phase 1 — Foundation

**Goal:** an Electron app that starts, launches the Python engine, proves the two can talk, and shows an empty app shell with light/dark theme. No PDF features yet.

This document also holds the project-wide decisions, architecture and conventions. Phases 2–7 assume them.

## Project overview

**PDFnix** is a Windows desktop PDF reader and editor (`productName` "PDFnix", `appId` `com.pdfnix.app`; set both when scaffolding). Features across all phases: read, zoom, rotate, search, highlight, comment, edit text, add text/images/shapes, signatures and initials, save, compress, password-protect, OCR, convert PDF to Word, page management, form filling, redaction, watermarks, further conversions, print.

Decisions already made:

| Topic | Decision |
|---|---|
| Stack | Electron + React/TypeScript UI, bundled Python engine (PyMuPDF) doing all PDF work |
| Edit depth | Add new content and modify/delete existing text by block replacement. No paragraph reflow |
| Licensing | Personal/internal use, so AGPL libraries (PyMuPDF/MuPDF) are acceptable |
| Platform | Windows 10/11 x64 only |

Phases:

1. Foundation (this document)
2. Viewer — open, render, zoom, rotate, thumbnails, outline, tabs, text selection, search
3. Annotations and save — highlight, comments, undo/redo, save
4. Content editing and signatures
5. Document tools — page management, forms, redaction, watermark
6. Processing jobs — compress, protect, OCR, conversions, print
7. Packaging and release

Out of scope for version 1: certificate-based digital signatures (PKCS#7/PAdES), paragraph reflow editing, cloud sync, collaboration, macOS/Linux builds, auto-update.

## Architecture

```
Electron main (TS) ──spawns──> Python engine (FastAPI on 127.0.0.1:<random port>)
      │ IPC through preload                              ▲
      ▼                                                  │ HTTP + token
Renderer (React + Vite + Tailwind + shadcn/ui) ──────────┘
```

- **The engine is the single source of truth.** Each open tab is an engine session holding a PyMuPDF `Document` as a working copy. The file on disk is not touched until the user saves.
- **The engine renders pages** to images. The renderer displays them and overlays a text layer, annotation handles and form inputs. There is no pdf.js: one renderer means what the user sees is exactly what is saved.
- **Every edit is an engine call** that mutates the document and returns which pages to re-render.
- **Long operations are jobs** (introduced in phase 6): started with one call, polled for progress, cancellable.
- **Main process** owns windows, native dialogs, the application menu, recent files, printing and the engine's lifecycle. It does no PDF work.

## Conventions

**Engine API**

- Base path `/v1`. Every request carries header `X-Engine-Token`; requests without the correct token get 401.
- Engine binds to `127.0.0.1` on port 0 (OS-assigned) and prints one line `ENGINE_READY port=<n>` to stdout. Main reads that line. The token is generated by main per launch and passed in the `PDFENGINE_TOKEN` environment variable.
- JSON in and out, camelCase field names. Errors: `{ "error": { "code": "…", "message": "…" } }` with a suitable HTTP status.
- Mutating calls return `{ "revision": n, "dirtyPages": [..], "pageCount": n }`. `revision` increases with every change to a document.
- The engine exits when its owner process disappears, so it can never be orphaned. Main passes its own PID in `PDFENGINE_PARENT_PID` and the engine watches that PID. The direct parent is not used because in development it is `uv` (and the venv's `python.exe` launcher), not Electron.
- Main passes the renderer's origin in `PDFENGINE_ALLOWED_ORIGINS` for CORS (the dev-server origin in development, `null` for a page loaded from `file://`). CORS preflight requests carry no token; the token is what protects the API.

**Coordinates**

- All API coordinates are PDF points (1/72 inch), origin top-left, in the page's *displayed* (rotated) space, the same as PyMuPDF's `page.rect`.
- The engine converts to unrotated space where PyMuPDF needs it (`page.derotation_matrix`). The renderer converts points ↔ CSS pixels with one shared helper: `px = pt × zoom × 96/72`.

**Renderer**

- State in zustand stores: `tabs` (open documents, per-tab page, zoom, revision), `tools` (active tool and its options), `settings` (theme, defaults; persisted by main with `electron-store`), `engine` (connection state and health for the status indicator).
- All engine access goes through one typed client, `src/renderer/src/api/engine.ts`. Components never call `fetch` directly.
- Images are fetched with the token header and shown via blob URLs.
- Light/dark follows `prefers-color-scheme`, which main controls through `nativeTheme.themeSource`. There is no `.dark` class: the stylesheet and Tailwind's `dark:` variant both key on the media query, so the theme is right before any script runs.
- Class names are merged with `cn` from the `cn` package (what the shadcn CLI now generates against), not a local `lib/utils` helper.
- Types shared by main, preload and renderer (the `window.api` contract, IPC channel names) live in `src/shared/api.ts`.

**Security**

- `contextIsolation: true`, `sandbox: true`, `nodeIntegration: false`.
- Content Security Policy allows `connect-src` and `img-src` only for self, `blob:` and `http://127.0.0.1:*`.
- The preload exposes a small typed API (`window.api`), nothing generic.

**Tooling**

- Node 24 + pnpm for the app. Python 3.12 + uv for the engine.
- Per the global guideline, file content is written with editor tools, not shell heredocs.

## Tasks

1. **Repository.** `git init`, `.gitignore` (node_modules, out, dist, `.venv`, `__pycache__`, build artefacts).
2. **Scaffold the app** with electron-vite's React + TypeScript template (`pnpm create @quick-start/electron`), into the project root. Confirm `pnpm dev` opens a window.
3. **UI kit.** Add Tailwind CSS and initialise shadcn/ui in the renderer. Add the components needed for the shell: button, tooltip, dropdown menu, dialog, tabs, separator, scroll area, sonner (toasts).
4. **Engine project.** `uv init` in `engine/`; dependencies `fastapi`, `uvicorn`, `pymupdf`; dev dependencies `pytest`, `httpx`, `ruff`.
   - `server.py`: FastAPI app, token dependency, error handlers, `GET /v1/health` returning engine and PyMuPDF versions.
   - `__main__.py`: bind port 0, print `ENGINE_READY port=<n>`, start the parent-PID watchdog, run uvicorn.
   - `sessions.py`: an empty registry of open documents (filled in phase 2).
5. **Engine lifecycle in main** (`src/main/engine.ts`):
   - Development: spawn `uv run python -m pdfengine` in `engine/`. Production path (`process.resourcesPath/engine/pdfengine.exe`) is wired but only used from phase 7.
   - Wait for the ready line with a timeout; show an error dialog with the captured stderr if it fails.
   - Restart once on unexpected exit and notify the renderer; kill on app quit.
6. **Preload bridge.** `window.api.engine.getConnection()` → `{ baseUrl, token }`; `window.api.app.getVersion()`; theme get/set.
7. **Typed engine client** in the renderer with `health()`; a small status indicator in the shell showing connected / reconnecting.
8. **App shell.** Top toolbar (placeholder buttons), empty tab strip, left side panel area (collapsed), central empty state ("Open a PDF or drop one here"), status bar. Application menu with File / Edit / View / Tools / Help entries, disabled until later phases implement them.
9. **Theme.** Light, dark and "follow system", persisted with `electron-store`; applied without a flash on start.
10. **Single instance.** `app.requestSingleInstanceLock()`; a second launch focuses the existing window (file hand-off is added in phase 2).
11. **Quality tooling.** ESLint + Prettier, vitest, ruff, pytest. Scripts: `pnpm dev`, `pnpm lint`, `pnpm typecheck`, `pnpm test`, `pnpm test:engine`.

## Verification

- `pnpm dev` opens the window; the status indicator shows the engine connected with its version.
- `pnpm test:engine`: health returns 200 with a valid token and 401 without one.
- Killing the engine process from Task Manager makes the app reconnect and report it.
- Closing the app leaves no `python`/`pdfengine` process running.
- Theme choice survives a restart.
- `pnpm lint`, `pnpm typecheck` and `pnpm test` pass.

## Done when

The shell runs, talks to the engine securely, recovers from an engine crash, and all checks above pass. The first commit is made at this point.
